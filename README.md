# windowsapp-va-sender v1.1.4

**Supported OS: Windows 10 22H2 / Windows 11 (x64).**


Stream a selected Windows application's video and process audio over SRT or RTMP.

## Use cases

Send a selected Windows application's video and audio to a receiving server, for event production, presentations, demonstrations, tournaments, and community broadcasts.

## Quick start

1. Extract the entire ZIP to a writable folder and open windowsapp-va-sender.exe.
2. On first launch, the app downloads the pinned official BtbN FFmpeg build (about 211 MB) and verifies its SHA-256.
3. Start your application and keep its window visible. Press REFRESH, then choose its window under APPLICATION. Its process audio is selected automatically.
4. Open SETTING, choose your options, and press SAVE.
5. Enter the organizer's receiving server URL under OUTPUT and press START. Press STOP to stop sending.
6. Use TEST for a 20-second local video/audio preview in ffplay. TEST does not publish to your destination server.

The application list shows the executable, PID and window title. Select the application window you want to capture. Audio is captured from the selected window's owning process and its descendants. Distinct processes with the same executable name are kept separate.

Targets are not stored in settings.json. Select the application each time you open the sender. REFRESH preserves a selection only while the same window and process instance still exists. After restarting an application, refresh and select it again. The selection is locked while sending or testing.

## Audio / video sync

SETTING → AUDIO SYNC (ms) adjusts audio relative to video. Default: 0. Range: -2000 to +2000 ms.

- If audio is about 0.2 seconds late relative to video, try **-200 ms**.
- Negative values advance audio by trimming that duration from the beginning and rebasing its timestamps.
- Positive values delay audio by adding silence at the beginning.
- Use small changes and compare a visible action with its sound. Test the actual receiving player, too.

This corrects relative A/V alignment. It does not remove network, server or player latency when comparing the source PC's direct sound with the received stream. The raw audio input is already initialized before the video filter, so swapping the order alone is not a demonstrated fix for a 200 ms offset.

Audio sync is applied in normal and CUSTOM modes and is saved with your settings.

## Language

English is the default. SETTING → LANGUAGE → ENG / JPN → SAVE changes and saves the interface language. Raw FFmpeg, ffplay and Windows diagnostics retain their original text.

## Encoding settings

| Resolution | 30 fps | 60 fps |
|---|---:|---:|
| 960x540 | CBR 3 Mbps | CBR 4 Mbps |
| 1280x720 | CBR 4.5 Mbps | CBR 6 Mbps |
| 1920x1080 | CBR 6 Mbps | CBR 8 Mbps |

Keyframe interval: 1 second. B-frames: 0. Audio: 128 kbps.
Default: SRT / 1280x720 / 30 fps / NVEnc P3 / Opus / audio sync 0 ms.

- SRT: MPEG-TS, AAC or Opus; srt:// URL.
- RTMP: FLV, AAC; rtmp:// or rtmps:// URL. RTMP TEST also uses FLV.
- CROP: preserve aspect ratio and crop the center.
- COMPRESS: stretch to the selected 16:9 resolution.
- LETTER-BOX: fit the whole image and fill unused space with black.
- CPU: libx264 / veryfast / zerolatency.
- NVEnc: h264_nvenc / P3 / ll / zerolatency.
- AMD: h264_amf / ultralowlatency / speed.

CUSTOM accepts output encoding options as -option value pairs. The app manages input capture, URL, mapping, filters, output format and preview duration. RTMP enforces AAC / 128 kbps / 48 kHz / stereo without duplicate audio options.

## Compatibility

- Windows 10/11 x64 with .NET Framework 4.8.  No .NET 8 Runtime installation is required.
- GPU encoding requires compatible NVIDIA or AMD hardware and drivers.
- Pinned FFmpeg: BtbN N-124714-g49a77d37be-20260531.
- Keep the target window restored. Capture availability depends on the application and Windows capture permissions; protected windows may not work.
- A process can own multiple windows. Their audio cannot be separated if it comes from the same process. Audio generated by unrelated processes is not automatically captured.
- STOP and app exit close only this sender's helper processes.
- No sub-0.5-second end-to-end latency guarantee is made.

## Known selection issues

AION2 and Endfield were excluded because .NET Framework Process.HasExited returned access denied. Version 1.0.1 uses PROCESS_QUERY_LIMITED_INFORMATION for process identity and exit checks in both selection and audio capture. AION2 and Endfield capture, TEST, and sending were subsequently confirmed by the user. Restore minimized windows before TEST or START.
